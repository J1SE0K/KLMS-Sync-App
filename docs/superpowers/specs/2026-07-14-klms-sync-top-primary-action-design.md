# KLMS Sync 최상단 전체 동기화 액션 설계

## 배경

Mac, iPhone/iPad, Windows 앱 모두 전체 동기화를 가장 중요한 사용자 행동으로 제공하지만 현재 기본 대시보드의 명령 패널 안에 배치되어 있다. 특히 중간·좁은 화면에서는 요약 콘텐츠 뒤로 내려가 사용자가 스크롤하거나 실행 패널을 찾아야 한다.

## 목표

- Mac, iPhone/iPad, Windows에서 `전체 동기화`를 공통으로 최상단 기본 액션으로 제공한다.
- 시스템 내비게이션과 인증 번호·로그인 필요·오류 같은 긴급 알림은 계속 더 높은 우선순위를 갖는다.
- 현재 넓은 화면의 구조, 색상, 카드 계층과 개별 동기화 기능을 유지한다.
- 창 크기나 기기 폭이 실시간으로 바뀌어도 버튼이 잘리거나 사라지지 않고 현재 실행 상태를 유지한다.
- 새 API를 만들지 않고 각 앱의 기존 실행·중단·WebSocket 상태 흐름을 재사용한다.

## 선택한 접근

`전체 동기화` 기본 액션을 기존 명령 카드에서 전역 최상단 액션 영역으로 이동한다. 같은 액션을 두 곳에 중복하지 않는다. 파일, 과제/시험, 공지 개별 동기화와 보조 설정은 기존 명령 패널에 남긴다.

전체 명령 패널을 통째로 위로 옮기면 현재 대시보드의 정보 계층과 넓은 화면의 3열 구성이 크게 흔들린다. 플로팅 버튼은 작은 화면에서 콘텐츠와 알림을 가릴 수 있다. 최상단 전용 액션은 기존 레이아웃을 가장 적게 바꾸면서도 전체 동기화의 발견성을 보장한다.

## 공통 동작

- 대기 상태에서는 `전체 동기화`와 실행 아이콘을 표시한다.
- 전체 동기화 실행 중에는 같은 컨트롤이 `전체 동기화 중단`으로 바뀐다.
- 다른 명령이 실행 중이거나 요청 제출이 진행 중이면 잠금 상태로 비활성화한다.
- 연결 정보가 없으면 실행하지 않고 기존 연결 안내와 오류 표현을 사용한다.
- 서버가 돌려준 명령 UUID가 확정되기 전에는 중단 요청을 보내지 않는 기존 보호를 유지한다.
- WebSocket 이벤트와 낙관적 상태가 도착하면 재로딩 없이 버튼의 실행·중단·잠금 상태가 즉시 바뀐다.
- 긴급 인증·로그인·오류 알림은 버튼보다 위에 표시하며 가리지 않는다.

## 플랫폼별 배치

### Mac

- `MacAlertBannerView` 아래, 작업 공간의 스크롤 콘텐츠 위에 최상단 액션 영역을 둔다.
- 넓은 화면에서는 작업 공간 제목·상태와 같은 헤더 줄에 적절한 고정 폭으로 배치한다.
- 중간·좁은 화면에서는 제목 아래에서 가로 전체 너비를 사용한다.
- 기존 `CommandPanelView`는 상태 스트립, 파일·과제/시험·공지 동기화, 메일 분석기와 실행 중 상세를 유지하되 전체 동기화 카드만 제거한다.

### iPhone/iPad

- 각 작업 공간의 `CompanionScreenContainer` 최상단 액션 영역에 배치해 어느 탭에서도 접근 가능하게 한다.
- 인증·로그인·오류 attention inset이 있으면 그 아래에 둔다.
- iPad 넓은 화면에서는 제목과 나란히 제한된 폭으로, iPhone과 중간 폭에서는 제목 아래 전체 너비로 바뀐다.
- 기존 `RemoteDashboardSyncCard`에는 개별 동기화와 관련 보조 정보만 남긴다.

### Windows

- 기존 `.topbar`의 첫 번째 주요 액션으로 배치하고 새로고침·상태 복사는 보조 액션으로 유지한다.
- 좁은 화면에서는 전체 동기화가 첫 행의 전체 너비를 차지하고 보조 버튼은 다음 행으로 흐른다.
- 사이드바의 원격 실행 패널에서는 전체 동기화를 제거하고 개별 동기화와 공지 메모 설정을 유지한다.

## 반응형 규칙

- 넓은 화면에서는 헤더 텍스트와 기본 액션이 한 줄을 공유한다.
- 공간이 부족해지면 기본 액션이 텍스트 아래의 별도 행으로 즉시 재배치된다.
- 최소 클릭 높이는 44pt/px 이상으로 유지하고 긴 실행 상태 문구는 한 줄 축소 또는 안전한 줄바꿈을 사용한다.
- 크기 전환은 선택된 작업 공간, 실행 명령, 서버 revision, 스크롤 대상 데이터를 초기화하지 않는다.
- 버튼은 플로팅 오버레이로 콘텐츠를 덮지 않는다.

## 오류 및 경쟁 상태

- 기존 세션 generation, operation owner, 제출 중 상태와 서버 UUID rekey 규칙을 그대로 사용한다.
- 오래된 HTTP 응답이나 이전 연결의 WebSocket 이벤트는 새 버튼 상태를 되돌릴 수 없다.
- 전체 동기화 실행 실패 시 버튼은 서버의 최종 상태와 기존 오류 메시지를 반영한다.
- 중단이 확정되면 `.cancelled`를 표시하며 실패로 오인하지 않는다.

## 검증

- Mac 접근성 스모크에서 1200 → 900 → 640 → 1200 리사이즈 동안 최상단 버튼의 가시성, 선택 작업 공간, 실행 상태를 확인한다.
- iPhone과 iPad UI 매트릭스에서 모든 주요 작업 공간의 최상단 버튼과 compact/wide 전환을 확인한다.
- Windows Playwright에서 넓은·중간·좁은 폭 모두 스크롤 전 버튼이 보이고 WebSocket 상태 변화가 즉시 렌더링되는지 확인한다.
- 세 플랫폼 모두 전체 동기화가 한 번만 노출되고 개별 동기화가 기존 위치에 남는지 정적 회귀 테스트를 추가한다.
- 전체 Python, Swift, Windows, Cloudflare relay 테스트와 설치된 Mac 앱 접근성 스모크를 다시 실행한다.

## 범위 밖

- 동기화 API, 명령 종류, 권한 정책, 서버 데이터 모델은 바꾸지 않는다.
- 플로팅 원형 버튼이나 별도 하단 실행 바를 추가하지 않는다.
- 사용자의 실제 KLMS 계정으로 동기화를 강제 실행하거나 Calendar, Reminders, Notes 데이터를 변경하는 검증은 하지 않는다.
