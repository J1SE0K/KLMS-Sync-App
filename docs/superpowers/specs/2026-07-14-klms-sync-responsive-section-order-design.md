# KLMS Sync 반응형 동기화 섹션 순서 설계

## 배경

`전체 동기화`는 원래 각 앱의 동기화 섹션에 속한다. 앞선 구현은 “좁은 화면에서 동기화가 맨 위”라는 요구를 버튼만 전역 헤더로 이동하라는 뜻으로 잘못 해석했다. 이 변경은 버튼을 동기화 섹션에서 분리했고, iOS에서는 대시보드가 아닌 화면에도 버튼을 노출했다.

## 승인된 동작

- `전체 동기화` 버튼은 파일·과제/시험·공지 동기화와 함께 기존 동기화 섹션 안에 둔다.
- 넓은 화면의 기존 다열 배치와 섹션 순서는 유지한다.
- 컨테이너가 좁아져 섹션들이 한 열로 쌓일 때만 동기화 섹션 전체를 첫 번째로 배치한다.
- 같은 실행 액션을 헤더와 동기화 섹션에 중복하지 않는다.
- 창 크기가 실시간으로 바뀌어도 선택 항목, 실행 명령, 서버 revision과 WebSocket 연결 상태를 초기화하지 않는다.

## 플랫폼별 배치

### Mac

- `DashboardTopBarView`에는 화면 제목, 상태와 기존 유틸리티만 남긴다.
- `전체 동기화`를 `CommandPanelView`의 상태 표시와 개별 동기화 버튼 사이에 원래 크기의 주요 카드로 복원한다.
- 넓은 화면은 동기화 열 왼쪽, 대시보드 요약 오른쪽 배치를 유지한다.
- 중간·좁은 화면은 동기화 열을 먼저 놓고 대시보드 요약을 그 아래에 놓는다.

### iPhone/iPad

- 공용 `CompanionScreenHeader`에서는 전체 동기화 버튼을 제거한다.
- 버튼을 `RemoteDashboardSyncCard` 안에서 개별 동기화 버튼보다 먼저 표시한다.
- 넓은 화면의 3열·2열 구성은 유지하고, 최종 1열 fallback의 첫 섹션을 동기화 카드로 유지한다.
- 로그·설정 등 대시보드가 아닌 화면에는 전체 동기화 버튼을 표시하지 않는다.

### Windows

- `#primarySyncButton`을 topbar에서 원격 실행 `.commands-panel` 안으로 복원한다.
- 기존 고유 ID와 실행·중단·WebSocket 렌더링 로직을 재사용한다.
- 1040px 이상에서는 기존 연결 → 원격 실행 사이드바 순서를 유지한다.
- 1039px 이하에서 패널이 한 열로 열리면 원격 실행 → 연결 순서로 배치하고, 메뉴를 열 때 원격 실행 섹션을 기본 대상으로 삼는다.

## 상태 및 오류 처리

- 대기 중에는 전체 동기화 실행, 실행 중에는 동일 컨트롤에서 중단을 제공한다.
- 다른 명령 실행 중, 요청 제출 중 또는 연결 미설정 상태에서는 기존 비활성화 규칙을 사용한다.
- 서버 UUID가 확정되기 전 잘못된 취소 요청을 보내지 않는 identity 보호를 유지한다.
- 이전 연결의 WebSocket 이벤트나 느린 HTTP 응답이 현재 상태를 되돌리지 못하도록 기존 generation·revision 검사를 유지한다.
- 이 작업은 동기화 API, 서버 데이터 모델과 실제 KLMS 동기화 흐름을 변경하지 않는다.

## 검증

- Mac: wide → medium → compact → wide 전환에서 동기화 섹션이 1열의 첫 섹션인지, 선택 작업 공간이 유지되는지 접근성 프레임으로 확인한다.
- iOS: iPhone·iPad 매트릭스에서 대시보드 카드 내부에 버튼이 하나만 있고 로그·설정에는 없는지 확인한다.
- Windows: 1040px에서 기존 순서, 1039px와 640px에서 원격 실행 섹션 우선 순서와 버튼의 패널 내부 포함 관계를 Playwright로 확인한다.
- 세 플랫폼 모두 실행/중단 identity 테스트, WebSocket 즉시 반영 테스트와 전체 회귀 테스트를 다시 실행한다.
- 실제 사용자 KLMS 동기화는 검증 중 실행하지 않는다.

## 범위 밖

- 전역 고정 버튼, 플로팅 버튼 또는 중복 실행 컨트롤을 추가하지 않는다.
- 동기화 명령 종류, 권한 정책, Calendar·Reminders·Notes 쓰기 동작은 변경하지 않는다.
